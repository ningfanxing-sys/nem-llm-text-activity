# CONF feature contract (design freeze; no window feature build)

The author adopts FEATAUDIT `REDESIGN.md`. This file fixes the projection and its source support, not evidence of forecast performance. No confirmation price, RRP, demand, P5MIN, forecast-value or outcome-label table is opened. All public document-valued feature and encoder calls require `code/guard.py`'s later `ExecutionPermit`. Importing the modules performs no data reads or inference.

## 1. Common support, source clock and missing labels

News origins are 00:00 fixed AEST (Australia/Brisbane), NSW1/QLD1/TAS1; the unchanged numeric block is NEWSD's 72-hour history, historical-field observation masks and calendar/region/horizon indicators, predicting the 24 hourly targets of the issue day. Numeric value construction is delegated to the frozen NEWSD/DAPANEL contracts and the later panel build. N excludes operator price forecasts and P5MIN. No day-d exogenous forecast exists in this information set.

The primary news source set is the deterministic, unique saved article version whose `saved_version_available_utc` lies in **(issue−72 h, issue]**, with publication no later than issue. The only window sensitivity is **24 h**, changing M and every compared content projection together. It is a rolling saved-version window, not the former completed-publication-day cohort. The availability proxy remains `max(publication_utc, modified_utc)+5 minutes` from NEWSX; actual capture remains separate provenance. It does not authenticate the first publication body or historical availability. No extra delay sensitivity is registered.

Version identity is article ID plus normalized text hash and source clocks. Exact duplicate versions collapse; conflicting same-ID text/clocks stop the source integration rather than choosing a version by its apparent usefulness. A raw source admitted to M is admitted to **all** content arms, including extraction failures. M adds `article_count` and `extraction_failed_count`; every news content arm includes both. Failure produces an explicit Unknown serialization and increments `tier_Unknown` in L_count, without invented statements. No statement or semantic feature is recovered from the body for the structured arms. The raw/word arms retain the same failed source article. A zero-document origin has counts zero and a 384-zero embedding; an admitted failed document is not a zero-document origin.

Notice origins and target keys follow RF2/B4/B6. Source availability remains RF2's conservative official notice clock (`ceil5(LASTCHANGED+5 minutes)` where that contract supplies LASTCHANGED). All notice arms share the same complete legal source **prefix**, availability ≤ issue, including messages older than six hours. M_notice adds distinct `notice_prefix_count`, distinct `notice_arrivals_6h` for (issue−6 h, issue], and `notice_failed_prefix_count`. Failed labels are retained as an engineering missing state common to every content arm; they supply no guessed live interval/MW. Complete source coverage is a prerequisite for interpreting zero counts. The August–September confirmation uses July 27–31 lead-in, not incomplete March–July archive months as no-notice days. Historical training coverage and weights are fixed in PROTOCOL_CONF.md.

## 4. MiniLM lock, overflow, cache and installation

Official model: `sentence-transformers/all-MiniLM-L6-v2`, immutable revision **1110a243fdf4706b3f48f1d95db1a4f5529b4d41**. `ENCODER_LOCK.json` records actual config/tokenizer URLs, SHA-256 and bytes; config/tokenizer files are under `model_lock/`. The official revision's architecture max positions=512 and tokenizer model_max_length=512, but its frozen SentenceTransformer `max_seq_length`=256. The tokenizer's single-sequence postprocessor adds [CLS] and [SEP] (2 tokens), so the registered content chunk budget is **L=254**, `min(512,512,256)−2`. This preserves the package's effective configured cap. No guessed 510-token budget or implicit truncation is used. Output is 384-dimensional CPU float32 mean-token pooling, per-chunk L2 normalization, equal chunk mean, final L2 normalization.

Primary: tokenize the **whole serialized corpus** without special tokens or truncation, partition into contiguous non-overlapping ≤254-token blocks, add specials to each block, encode each block and average all blocks equally. Only overflow sensitivity: encode the first block. Chunk mean is a transparent engineering adaptation because Chen does not specify overflow. A shorter final block has the same weight as other chunks. Report token/block counts and original field-text completeness. Do not call article-wise means the Chen concatenation chain. E_raw and L_chen share output dimensions/overflow rules but not token length; no equal effective-capacity claim follows.

`code/encoders.py` verifies model config/tokenizer hashes and weight hash, locally loads CPU float32, sets Torch one thread, and disables inference gradients. No model load or inference occurs now. Chunks are cached by exact canonical token-ID-block SHA-256; same clock/serialized prefix across notice horizons is reused. Cache eviction changes speed only. The code uses chunk batch 1 (≤8); an executor can batch up to eight identical operations without changing the projection. Stream one origin at a time; do not hold all origin embeddings/corpora in memory. A 10,000-vector float32 chunk cache is bounded; persisted chunk cache must include revision and exact token block identity.

## 5. Placebos: secondary project diagnostics, no top-venue template

Both are explicitly `PROJECT_CHOICE_NO_TEMPLATE`; no cited top-venue paper supplies these procedures. The concrete arm instances and priority are in PROTOCOL_CONF.md's fixed run list.

P_shift shifts publication/modification/saved-version availability/registration clocks **and every parsed event start/end, action time and forecast target date** together by +28 days. Unresolved dates remain Unknown with a parse-status diagnostic. Raw source literals remain immutable. Admit only originally past source records whose shifted clock is legal; no wrapping confirmation future records to earlier origins. Construct the shifted arm's own M_shift on its shifted support, with identical missing-state columns. P_shift versus original M is a time-shift diagnostic; only versus M_shift addresses activity on shifted support. No 56-day sensitivity is registered.

P_content retains recipient origin source slots, their number, publication/edit/availability clocks, source missing states and target calendar. Donor bundles must have the same region, AEST year-month, weekday and exact admitted document count, and every donor version must already be visible **before the recipient origin**. Their ordered extraction-status mask must match the recipient mask: this implements the required preservation of engineered missing states, rather than filling a failed recipient or creating a hidden failure in a valid recipient. Canonical donor identity is the sorted tuple of `source_document_ids`, not its origin/bundle identifier: exclude an identical recipient source-ID tuple and require at least **two distinct source-document bundles**. Repeated origins with identical documents count once; choose their earliest legal origin (then bundle ID lexicographically). Seed **20261001** chooses deterministically by SHA-256 of `seed|recipient_bundle_id|canonical donor source-ID tuple` (canonical compact JSON). Map donor documents to recipient slots in their frozen source order; exchange content and extracted semantic package together. Parsed event dates transfer by their donor-publication relative offset to recipient publication; raw evidence/literals stay as immutable donor provenance. Preserve recipient failure status; do not impute a successful donor semantic package into a failed recipient slot. Report donor date differences, unmatched slots and reuse. No weekday relaxation is allowed.

A globally bijective permutation of all month-origin bundles cannot also be past-only for earliest origins. This is therefore the REDESIGN conditional, past-only **bundle reassignment** implementation of the project permutation diagnostic, with donor reuse across distinct origins disclosed. Within a recipient bundle use each donor document once. Strict full-prefix notice count matching can yield little or no coverage; report `NO_VALID_PERMUTATION` if no legal matches instead of relaxing the strata. Score the original/reference/placebo predictions only on identical eligible matched target keys; unmatched originals are excluded from the placebo diagnostic, never from primary evaluation. Original M is unchanged. This diagnostic cannot establish a causal semantic mechanism.
